## 二、逐项改动

### P0-01 拖拽落点永远在画布左上角

- 现象：`Stage.dropHandler` 固定按 `top:0/left:0` 写入，拖到哪都落在左上角。
- 改法：按鼠标真实落点换算——`stage.getBoundingClientRect()` → 扣除边框 → 除以当前缩放 → 再减元件自身宽高的一半（居中对齐光标），最后仍走 `fixElementToParentBounds` 做边界收敛。
- 文件：`src/views/layouteditor/components/editor/main/Stage.vue`
- 验证：代码级修复；落点换算公式与同一套 `getViewportCenter()`（实测生效，见 P0-02）共用坐标系。

### P0-02 点击新增元件全部堆叠在原点

- 现象：元件库点击新增一律写 `top:0/left:0`，多个元件完全重叠。
- 改法：新增 `findFreeSlot(element, page, anchor)`——以「可视区域中心」为锚点，按曼哈顿距离扫描 `20px` 网格，`8px` 间距判定重叠，返回最近空位；画布排满时返回 `free:false` 并回退到起点。
- 文件：`src/helpers/positionDimension.js`、`src/views/layouteditor/components/editor/drawer/ElementsMenu.vue`
- **实测**：可视中心锚点 → 第一个容器落 `left:460, top:0`，第二个落 `left:780, top:0`，两者 `300px` 宽互不重叠（改前均为 `0/0`）。

### P0-03 缩放不可控：无「适应画布 / 100% / 缩放到选中」，且窗口变化会覆盖用户缩放

- 现象：底部只有放大/缩小/百分比；`resizeHandler` 用坏正则取页面尺寸，窗口一动就把用户设的缩放覆盖掉。
- 改法：新增 `helpers/zoom.js` 作为缩放口径唯一来源（`MIN_ZOOM 0.1` / `MAX_ZOOM 4` / `ZOOM_STEP 1.25` / `clampZoom`）；`ZoomMenu` 增加 **适应 / 100% / 选中** 三个按钮；`resize.js` 重写为 `isZoomAuto` 状态机——用户手动缩放后不再被窗口 resize 覆盖，改为读 `#canvas-main` 的真实尺寸计算适配；**缩放到选中**按选中元素包围盒 + 80px 留白计算缩放并居中。
- 文件：`src/helpers/zoom.js`（新增）、`.../editor/common/ZoomMenu.vue`、`.../mixins/resize.js`、`.../editor/main/index.vue`
- **实测**：页面 1200×400、可视区 1005×876 时自动适配 `zoom = 0.818`（= (1005-24)/1200，符合预期）；三个按钮在位，无选中时「选中」为 disabled。

### P0-04 Shift 点选多选失效（且会顺手把元件拖走）

- 现象：`MrEl` 上挂了三个 mousedown 监听（`.exact` / `.meta` / `.ctrl`），Shift 加选被吞；且 Shift 按下仍进入拖拽，导致「想加选结果拖动元件」。
- 改法：`MrEl` 合并为单个 `mouseDownHandler`（只判左键）；`StageEl.activatedHandler` 用 `e.shiftKey || e.metaKey || e.ctrlKey` 实现**切换选中**（已选中则移出）；`MrContainer` 在按住修饰键时**不进入拖拽**。
- 文件：`.../editor/common/mr-vue/MrEl.vue`、`.../editor/main/StageEl.vue`、`.../editor/common/mr-vue/MrContainer.vue`
- **实测**：普通点击单选 → Shift 点第二个元件得到 2 个选中 → 再 Shift 点一次该元件移出，行为符合多选惯例。

### P0-05 框选只认顶层子元素，无法选中/进入容器

- 现象：`selectStopHandler` 只遍历 `page.children`，不递归、不认缩放；容器内的元件框选不到，也没有父级选择手段。
- 改法：`getAbsoluteBox` 改为**逐级累加所有 `data-mr-el` 祖先偏移**（旧实现要求「父级的父级也是 MrEl」才继续，深层容器必然算错）；框选遍历当前层级子树并支持 **Shift 追加**；新增**层级面包屑**（「页面 / 容器名」，可点击回退）、**双击容器进入下一层**、**Esc 逐级返回**。
- 文件：`src/helpers/positionDimension.js`、`.../editor/main/Stage.vue`、`.../editor/main/index.vue`、`.../editor/main/StageEl.vue`
- **实测**：双击容器 → `editorScopeId` 指向该容器、容器被选中、面包屑显示「页面 / Line + 提示文案」；第一次 Esc 清空选中、第二次 Esc 退出容器层级、面包屑消失。

### P0-06 撤销粒度太细：每敲一个字符算一步

- 现象：文本输入每字符触发一次 mutation，一次改名能塞满历史；同一次拖动/连续微调也各占一步。
- 改法：文本输入 **400ms 防抖合并**（并在输入时锁定发起编辑的对象，避免防抖窗口内切换选中改错对象）；撤销历史 **500ms 内同目标连续改动合并**为一步；`DimPos` 的勾选框等离散操作标记 `instant` 立即提交；卸载前冲刷待提交改动。
- 文件：`.../mixins/redoundo.js`、`.../editor/drawer/settings/SettingsMenu.vue`、`.../settings/submenus/ElementSettings.vue`、`.../settings/submenus/controls/DimPos.vue`
- **实测**：删除元件后 `Ctrl+Z` 能完整恢复（历史链可用）。

### P0-07 页面管理有代码无入口

- 现象：`duplicatePage` / `removePage` / `_togglePageDialog` 早已存在，界面上没有任何入口；页面抽屉只有「元素 / 设置」两个页签。
- 改法：抽屉补上第三个 **「页面」** 页签（指示条 240px/3 = 80px 同步位移），新增 `PagesMenu.vue` 面板：页面列表 + 选中态 + hover 显示的重命名/复制/删除 + 「新建页面」按钮 + 与页面设置对话框的联动提示；删除二次确认，**保留至少 1 个页面**；顺带修掉 `duplicatePage` 传参 bug（`payload.el` → `compRef(comp)`）。
- 文件：`.../editor/drawer/PagesMenu.vue`（新增）、`.../editor/drawer/index.vue`、`src/store/modules/layoutEditor.js`
- **实测**：页签 `['元素','设置','页面']`，切到「页面」后指示条 `left:160px; right:0`，面板列出页面 `Home`、「新建页面」按钮与说明文案在位。

### P0-08 无保存动作，且保存状态永远显示「有未保存改动」

- 现象：工具栏没有保存按钮；`checkLastSaved` 读的是从未写入过的 `'gh-last-saved'` 键，等于永远脏。
- 改法：新增 `saveProject` action（写 `local-saved` 快照 + 记录 `lastSavedAt` + 置 `hasChanges=false`）；`checkLastSaved` 改为与真实快照比对；工具栏新增**保存按钮**，标题右侧新增**保存状态胶囊**（绿点「已保存 HH:mm」/ 橙点「有未保存的改动」/ 「尚未保存」，tooltip 汇总草稿与快照时间）；`hasChanges` 为真时关闭页签前给出浏览器原生的离开确认。
- 文件：`src/store/modules/layoutEditor.js`、`src/store/types.js`、`.../editor/header/ActionBar.vue`、`.../editor/header/index.vue`、`src/views/layouteditor/components/Editor.vue`
- **实测**：点保存 → 顶栏出现 toast「已保存到本地快照」，状态胶囊变「已保存 18:26」且圆点类名切到 `save-dot--saved`。

### P0-09 全流程零操作反馈

- 现象：删除/复制/剪切/保存/加载都没有任何提示，用户不知道操作是否生效。
- 改法：新增 `mixins/notify.js` 作为统一反馈入口（`notifySuccess/Warning/Info/Error`，经 `$root` 事件交给 `Editor.vue` 统一渲染 `$message`，全站只此一个 toast 宿主）；删除/复制/剪切/保存/加载/清空/画布排满等路径全部补齐文案；`ConfirmDialog` 文案从「删除后所有本地更改将丢失！」改为如实描述（「确定要清空…可用 Ctrl+Z 撤销」，按钮「删除」→「清空」）。
- 文件：`.../mixins/notify.js`（新增）、`src/views/layouteditor/components/Editor.vue`、`.../editor/main/Stage.vue`、`.../editor/header/ActionBar.vue`、`.../editor/dialogs/ConfirmDialog.vue`、`.../editor/drawer/ElementsMenu.vue`、`src/views/layouteditor/index.vue`、`.../editor/dialogs/LoadDialog.vue`
- **实测**：保存 →「已保存到本地快照」；Delete 删除元件 →「已删除 1 个元件，可用 Ctrl+Z 撤销」。

### P0-10 工程文件读取无校验、失败静默

- 现象：加载外部工程时坏 JSON / 空文件 / 老格式都会静默失败或崩在后续渲染。
- 改法：新增 `encodeProject / decodeProject / assertProject`（兼容裸 JSON 与 Base64 档案、剥 BOM、坏 JSON 抛可读中文错误、校验 `pages` 非空且每页有 `id`）；`normalizeProject` 补齐 `version` 与缺失字段、保留旧字段映射；`loadProject / downloadProject / saveProject / clearProject` 统一返回 `{ok, ...}` 结构，调用方按成功/空/失败三种情况分别提示；顺带修掉 `downloadProject` 的 MIME 拼写错误（`appliction/json` → `application/json`）与 `clearProject` 的 `state.commit` 误用。
- 文件：`src/store/modules/layoutEditor.js`、`src/store/types.js`、`src/factories/projectFactory.js`、`.../editor/header/ActionBar.vue`、`.../editor/dialogs/LoadDialog.vue`、`.../editor/dialogs/ConfirmDialog.vue`
- 验证：代码级 + 首次进入（无本地草稿）时不会弹任何误导性提示（**实测**：全新来源打开时控制台只有 `Base state saved`，无 error、无 toast）。

## 四、已知残留（本轮未做，如实记录）

1. **「从远端加载工程」仍未接入**：原实现实际读取的就是本地草稿。本轮把对话框标题改为「加载工程」，并加了一行说明「当前版本读取的是本地已保存的工程草稿，远端仓库加载尚未接入」，不假装已实现。
2. **框选范围限于当前层级**：进入容器后可框选该容器内的元件；跨层级的「一把框选全部后代」未实现（与面包屑的层级模型一致，故意保持可预期）。
3. **保存是本地快照**：`localforage` 单机存储，没有后端与多人协同。
4. **输入防抖 400ms / 历史合并 500ms 为固定值**，未做成可配置项。
5. **尺寸/位置控件对未挂载元素仍无兜底**：`getComputedProp` 依赖 DOM 节点存在，极端时序下（属性面板在元素未挂载时触发）仍可能报错，本轮未加保护。
6. **窄屏适配**：头部标题、保存状态、面包屑按桌面宽度排布，未针对 <1024px 做专项压缩。
